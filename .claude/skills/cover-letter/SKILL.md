# `/cover-letter [uuid 或 URL]` — 針對職缺生成 Cover Letter

## 與 `/cv` 的分工

- **`/cv` 負責「資格證明」**：自我介紹只陳述事實——做過什麼、做得多好，不寫求職動機或說服性語句。
- **`/cover-letter` 負責「說服」**：回答「為什麼是這家公司」「我能貢獻什麼」「為什麼該選我而不是其他候選人」，語氣可以個人化、有敘事性。
- 兩者共用同一份 `/source` 事實來源，**內容不可互相重複**——cover letter 不必再重述履歷已經列出的完整經歷條列，而是挑 1-2 個最相關的故事深入展開。

## 核心原則

1. **事實來源唯一**：所有內容必須基於 `/source` 目錄下的 Markdown 檔案（`resume-en.md`、`resume-zh-TW.md`）。禁止虛構經歷、技能或對公司的了解。
2. **雙語支援**：必須產生英文與繁體中文兩版。
3. **回答語言**：一律使用**繁體中文**與使用者溝通。
4. **不編造公司資訊**：對公司/產品/使命的描述必須來自實際抓取到的 JD 或公開頁面內容，不可憑空想像公司在做什麼。

---

## 第一階段：取得職缺與履歷資料

1. **判斷輸入**：
   - 若使用者提供的是 `/cv` 已產生過的 `{uuid}`（或公司名稱可對應到 `app/(download-pdf)/{uuid}/`），直接複用該資料夾內既有的 `jd.md`，不重新抓取。
   - 若使用者提供的是新的職缺 URL，比照 `/cv` 第一階段流程：使用 **chrome-devtools** MCP 抓取 `company_name` 與 JD → 失敗則改用 **firecrawl** → 仍失敗則請使用者手動貼上 JD 內容。
   - 若該職缺尚未透過 `/cv` 建立過履歷（找不到對應 `{uuid}`），詢問使用者是否要先跑 `/cv` 產生履歷，或僅產生獨立的 cover letter（此時仍需要一個資料夾存放輸出，可執行 `pnpm cv {company_name} {URL}` 取得 `{uuid}` 供 cover letter 使用，即使不生成 `page.tsx` 內容）。
2. 確認 `app/(download-pdf)/{uuid}/jd.md` 內容存在且完整。

---

## 第二階段：內容撰寫規範

### 結構（3–4 段，使用 `\n\n` 或 markdown 段落分隔）

1. **開場：為什麼是這家公司**——具體點出這家公司/產品/使命/技術挑戰吸引你的原因，必須對應到 JD 或公司頁面裡實際提到的內容，不寫「貴公司是業界領導者」這種空泛套話。
2. **貢獻：我能帶來什麼**——挑 1-2 個 `/source` 裡與 JD 最相關的具體經歷或成就深入展開（可以是履歷裡已有的成就，但用更完整的敘事方式重講一次，補上背景脈絡），說明這段經歷如何直接對應 JD 的需求或挑戰。
3. **差異化：為什麼該選我**——根據 `/source` 裡的真實特質（例如跨語言溝通能力、獨立端到端交付經驗、橫跨新創與大型企業的適應力等），說明相較其他候選人的獨特之處。**只能用 `/source` 裡有依據的特質，不可貼空泛標籤**（如「我很努力」「我熱情積極」）。
4. **結尾：呼應與行動呼籲**——簡短重申興趣，表達期待進一步討論的意願。

### 文字規範

1. **禁用詞**：不用 "Responsible for"、「負責」這類弱動詞開頭；不用未經事實佐證的自我評價形容詞（「優秀」「傑出」「熱情」）。
2. **具體優於空泛**：每個論點都要能連回 `/source` 裡的真實事蹟，不寫「我認為我很適合」這種無依據斷言。
3. **語氣**：可用第一人稱（"I" / 「我」），比履歷更口語、更有敘事性，但不浮誇。
4. **不逐條列點**：Cover letter 是連續段落文章，不用 bullet list（履歷才用 bullet）。
5. **數字用阿拉伯數字**：8 不寫 eight，30% 不寫 thirty percent。

### 字數上限

- **zh-TW 版**：全文（不含標點與空白）**600–800 字**。
- **en 版**：對應**約 300–400 words**（以空白分隔計算）。
- 寫完後實際數過字數確認合規；超過就刪減，優先刪「貢獻」段裡次要的舉例，保留最貼合 JD 的那一個。

---

## 第三階段：輸出檔案

寫入至履歷相同的資料夾，方便與該份客製化履歷配對：

- `app/(download-pdf)/{uuid}/cover-letter-en.md`
- `app/(download-pdf)/{uuid}/cover-letter-zh-TW.md`

每份檔案內容為純文字段落（不含 markdown 標題），可直接複製貼上到求職平台的 cover letter 欄位，或後續用 `pdf`/`docx` skill 轉成附件。

---

## 完成後

1. 回報 UUID 與寫入的檔案路徑。
2. 在回覆中直接附上兩版全文，方便使用者當場檢視、不用另外開檔。
3. 附上實際字數統計（zh-TW 字數 / en word count），確認在上限內。

## 決策點

- 若找不到對應 `{uuid}` 且使用者未指定 → 先詢問是否要連帶跑 `/cv`，或只需要獨立 cover letter 文字（此時仍建立 `{uuid}` 資料夾以存放輸出）。
- 若 JD 頁面無法抓取 → 依序嘗試 chrome-devtools → firecrawl → 請使用者手動貼上 JD。
- 若 `/source` 中找不到與 JD 直接相關的經歷可用於「貢獻」段 → 如實告知使用者這是真實的落差，不可編造經歷硬湊。
